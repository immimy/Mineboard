## GraphQL + Apollo

All database reads go through GraphQL via the Supabase GraphQL endpoint (`${supabaseProjectUrl}/graphql/v1`).

Types are auto-generated by `graphql-codegen` into `gql/__generated__/`. Run `npm run codegen` to regenerate after schema or query changes. Never hand-edit files in `gql/__generated__/`.

Import queries and fragments from `@/gql/__generated__` using the `graphql()` tag:
```ts
import { graphql, useFragment, FragmentType } from '@/gql/__generated__';
```

GraphQL scalar mappings (defined in `codegen.ts`): `UUID → string`, `Date/Time/Datetime → string`, `JSON → string`, `BigInt/BigFloat → string`, `Opaque → any`.

## Apollo client instances

Two clients — one for the server, one for the browser:

**Server** (`gql/apollo/ApolloClient.ts`): Uses `registerApolloClient` from `@apollo/client-integration-nextjs`. Export `getClient`, `query`, `PreloadQuery`.

⚠️ **Never** instantiate the Apollo client at module level in server actions or route handlers. Always call `getClient()` per request to avoid sharing session tokens across users.

**Browser** (`components/global/ApolloWrapper.tsx`): Wraps the app tree in `<ApolloNextAppProvider makeClient={makeClient}>`. The `makeClient` function creates a new client instance per render.

Both clients attach the Supabase JWT as `Authorization: Bearer <token>` and `apiKey` header on every request.

**Server action helper**: `utils/actions/graphql.ts` → `customQuery()` — wraps `getClient().query()` and throws on error. Use this instead of calling `getClient()` directly in actions.

## Route handlers

- `app/api/auth/route.ts` — OAuth callback (GET). Exchanges code for session.
- `app/api/sign-cloudinary/route.ts` — Signs Cloudinary upload params (POST).

## Server actions

Server actions live in `utils/actions/`. They use `'use server'` and return `FormState` (`{ data?, error: string | null }`). Pattern: call `authenticateUser(supabase)` first, then perform the operation.
